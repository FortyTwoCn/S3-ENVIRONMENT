# BME688 空气质量输出

固件 1.1.0 使用 Bosch BSEC 2.6.1.0（Arduino 包 `bsec2@1.10.2610`），替换原来的 Adafruit 原始驱动。GPIO8/9、模块接口及 PCB 不变。BSEC 独占 BME688 的加热器与测量调度，不能同时运行另一个 BME 驱动。

网页的实时卡片、历史表格、曲线及 CSV 包含以下全部通用测量输出：

|字段|含义|单位|
|---|---|---|
|`temperature_c`|BSEC 传感器自身加热补偿后的温度|°C|
|`humidity_pct`|BSEC 加热补偿后的相对湿度|%RH|
|`pressure_hpa`|气压|hPa|
|`gas_ohm`|原始气体电阻|Ω|
|`raw_temperature_c`|未作加热补偿的温度|°C|
|`raw_humidity_pct`|未作加热补偿的湿度|%RH|
|`iaq`|空气质量指数，0–500，越低越好|无量纲|
|`static_iaq`|静态 IAQ，不强制截断为 500|无量纲|
|`eco2_ppm`|CO₂ 当量 / eCO₂ 估计值|ppm|
|`bvoc_ppm`|呼吸相关 VOC 当量估计值|ppm|
|`gas_percentage`|相对历史基线的气体信号水平|%|
|`compensated_gas`|温湿度补偿后的气体信号，BSEC 对数域输出|无量纲显示|

eCO₂ 根据 VOC 与人体呼吸的平均相关性估算，BME688 不直接测量 CO₂。酒精、清洁剂、香水等 VOC 会影响估计。bVOC 也不是实验室分析的特定 VOC 浓度。相对气体水平不是 H₂S 概率、烟雾百分比或某种气体的 ppm。

用户要求的准确度、预热和校准状态不上传、不入库、不在网页显示。固件只在本地检查 BSEC 估计的 accuracy；0 级估计输出 `null`，网页显示 `--`，不会把初始占位值作为有效读数。原始温湿压和气体电阻仍正常输出。连续运行与环境变化有助于形成基线，不承诺固定时间达到准确度。

使用 Bosch 通用 `bme680_iaq_33v_3s_4d` 配置：BME688 兼容 BME68x 的 forced-mode IAQ 测量，3.3V 供电、LP 约 3 秒采样、4 天基线历史。没有加载特定气体分类模型。软件循环持续调用 BSEC，网站正常上报仍为 300 秒；“立即采样”等待下一个真实采样周期。主读数从 1.1.0 起变为补偿温湿度，因此和此前未补偿历史记录可能有合理偏移；可比较未补偿字段。

BSEC 自身加热补偿采用对应供电配置；额外 ESP32、外壳热偏移设置为 0，必须实测后才能另加。BME688 仍应远离 MQ / ESP32 热源。

高准确度基线首次可用时保存至独立 NVS 命名空间 `bsec-state`，随后最多每 6 小时保存一次。版本/配置标记不匹配或库拒绝的状态不会继续使用。Wi-Fi、网站令牌和设备策略的 NVS 配置保留。断电后下一次启动可恢复基线；本版本不上传这些内部状态。

特定气体扫描分类、四通道概率和气体回归输出需要另外配置 Bosch BME AI-Studio 模型；当前宿舍环境项目未配置。产品 F1 分数、标称扫描速度、响应时间、误差及功耗属于规格，不能从模块读取成实时数据。也不能用简单公式从电阻伪造 eCO₂ 或 H₂S 浓度。

数据库继续使用现有 JSONB，无须迁移，旧固件与旧历史记录的新字段为空。保留时长继续遵循网站的可配置策略。
